# 通知设置简化设计（待确认）

## 1. 目标与范围

保留“每个阶段可以独立决定是否通知”的能力，但默认只展示常用选择，避免把内部调度步骤全部摆在用户面前。

本文件是设计方案，不代表本次已经改动通知界面。现有通知设置在方案确认前保持不变。界面继续采用当前 Vuetify 的字体、间距、颜色、按钮与表单风格，不增加独立导航或大幅介绍横幅。

## 2. 页面结构

入口保持：设置 → 通知。页面只分三个区域：

### 通知服务

- 启用通知：总开关。
- 通知方式：密钥通知 / Webhook。
- 服务地址、密钥：按通知方式显示。
- 测试连接：显式发送测试消息，注明不受业务阶段开关限制；测试前先保存服务配置，避免测试旧地址。

总开关关闭后，业务通知不发送；下方选择保留但置灰，不清空原设置。

### 什么时候通知

默认只显示一个“通知方案”单选：

| 方案 | 行为 |
| --- | --- |
| 仅异常（推荐） | 最终失败、需要用户操作时通知；成功不通知 |
| 完成与异常 | 每条处理链最终完成一次，以及最终失败、需要用户操作时通知 |
| 自定义 | 展开阶段配置，分别选择开始、成功、失败与待处理事件 |

不提供“全部阶段”作为默认推荐，减少正常任务的通知轰炸。切换方案属于未保存编辑，统一点击页面底部“保存”后生效。

自定义以紧凑表格展示，手机端转为逐行卡片。开始、成功、失败是同一行的复选框，不再用六组折叠面板和二十多个平铺开关。

| 处理环节 | 开始 | 成功 | 失败 |
| --- | --- | --- | --- |
| 离线 / 种子下载 | □ | □ | □ |
| 种子下载后清理 | □ | □ | □ |
| 云端解压 | □ | □ | □ |
| 本地下载原包 | □ | □ | □ |
| 本地解压 | □ | □ | □ |
| 完成后处理 | □ | □ | □ |

表格下面只有两项独立开关：

- 需要我处理：等待密码、云处理超时待确认本地处理、状态异常待核对。
- 主动取消：用户手动取消任务后的通知，默认关闭。

低频细项放入“更多阶段”折叠区：离线提交成功、发现压缩包、清理预演完成，以及原包后处理 / 产物清理的独立成功和失败开关。折叠区不是第二套设置，修改同一事件配置；同组部分勾选时显示半选，避免丢失已有细分配置。

自定义模式下，下载成功和清理成功可以分别通知；如两项都选中，明确允许两条消息。页面用一行文字显示“当前预计：下载成功、清理成功、失败及待处理时通知”，不再提供占空间的阶段预览下拉框。

### 消息样式（默认折叠）

- 默认模板即可使用，不要求编辑模板。
- 展开后可以编辑模板、恢复默认，并查看一条示例；示例不实际发送。
- 保存按钮沿用当前设置页样式。

## 3. “完成与异常”的链路语义

这是一条处理链的最终结果，不是把所有步骤的“成功”都打开。

| 任务链 | 发送完成通知的时机 |
| --- | --- |
| 普通离线下载，无后续处理 | 115 明确确认下载完成 |
| 种子下载 + 清理 | 下载及清理都完成之后 |
| 种子清理仅预演 | 通知“下载完成，清理预演完成（未删除文件）” |
| 种子下载 + 清理 + 自动解压 | 关联压缩包全部结束，且后处理完成后；部分失败时不报全部成功 |
| 云解压正常完成 | 解压和已开启的完成后处理全部完成后 |
| 云解压转本地 | 云超时待确认时按“需处理”通知；本地链完成后再通知最终完成 |

多个压缩包使用同一来源任务汇总：例如“共 3 个，成功 2 个，失败 1 个”，附失败项；内部轮询、短暂重试不当成最终失败。

实现这项能力需要明确父子任务关联及最终结果汇总，不应只靠前端将若干旧阶段开关打开。完成判定必须使用持久化结果，不能因目录发现了部分文件就提前报成功。

## 4. 异常、重试与防重复

- 自动重试中的临时错误只进日志；耗尽重试或进入人工处理时再通知。
- 同一执行轮次的同一逻辑事件只发送一次；同一异常的反复轮询不重复通知。
- 手动重试开启新轮次，可再次发送结果。
- 云超时与“等待确认本地处理”是一个待处理事件，不连续发两条。
- 下载成功但清理失败应写“下载完成，清理失败”，不能写“下载失败”。
- 清理已成功但解压失败，要准确说明失败阶段，不能笼统写整条链下载失败。
- 通知发送失败与业务失败分开，通知失败不能改变下载或解压结果。
- 关闭阶段后，待发送事件标记为未发送；重新开启不补发历史消息。

## 5. 通知内容

默认消息只保留：结果标题、任务名称、失败或待处理原因、时间。子压缩包附所属种子名称。需要用户操作时给出操作提示；只有配置了可访问的应用地址才提供详情链接。

示例：

```text
种子处理完成
任务：示例资源
结果：下载完成，清理 12 个文件、3 个空目录
时间：2026-10-30 15:20
```

```text
需要确认本地处理
任务：示例压缩包.zip
原因：云处理超时，云队列已释放
操作：进入任务详情，选择下载到本地解压或取消
```

## 6. 兼容旧配置

- 不静默覆盖现有阶段选择。
- 升级后，旧细分配置进入“自定义”，完整保留，包括默认折叠的低频选项。
- 新安装推荐“仅异常”；老用户主动选择方案并保存后才切换。
- 旧版本无完整链路汇总能力时，不伪装为已支持“完成与异常”。后端就绪后再开放该方案。

## 7. 验收清单

- 首屏能快速完成“地址 + 密钥 + 仅异常 + 保存”，不必理解内部阶段。
- 自定义仍能控制每一类已有事件，关闭失败通知确实不发送。
- 下载完成但清理未结束时，“完成与异常”不提前报完成。
- 云转本地、多个子压缩包、预演、主动取消均能给出准确结果。
- 自动重试不刷屏，手动重试可以再次通知。
- 桌面和手机均沿用现有 UI 风格，未保存的操作不影响运行配置。

## 8. 建议实施顺序

1. 先完成父子链路结果汇总和事件去重，补齐链路测试。
2. 再将通知页收敛为“服务 / 通知方案 / 消息样式”三个区域。
3. 迁移旧设置为自定义，并验证保留所有现有选项。

## 9. 实施记录

已实现三个通知方案、紧凑自定义阶段表格、折叠消息样式，以及持久化结果汇总。
旧安装维持自定义配置；为避免改变旧数据库和无显式设置调用方的行为，未配置时仍按兼容模式运行，用户可主动切换到推荐的“仅异常”。
预设方案汇总父子任务和后处理结果，自动重试不发最终失败通知。关闭期间结果会被消费，重新开启不补发；手动重试通过执行边界允许新的结果通知。
